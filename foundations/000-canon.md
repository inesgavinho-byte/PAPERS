# Canon

The Canon states what is true within this body of thought.

It contains definitions only. Arguments live in `dialogues/`. Applications live in the published Papers. The direction is fixed and never reversed:

Dialogue → Canon → Paper

The Canon is not a repository of definitions. It is a consistency engine. Its purpose is to ensure that, decades from now, every Paper reads as the work of a single mind obeying the same conceptual boundaries.

## Rules of entry

A definition enters the Canon only when it has passed four tests in dialogue:

1. It explains the phenomena that follow from it.
2. It is more powerful than the current definition in use elsewhere.
3. It is falsifiable — situations can be imagined in which it fails, and it survives them.
4. It creates new questions rather than closing inquiry.

A fifth test, implicit in the first three dialogues and made explicit by the third:

5. A definition must privilege mechanisms over consequences. It names the causal structure that generates the phenomenon, never the phenomenon itself. This is the epistemological signature of the discipline: identity by architecture, not members (Dialogue 001); preservation, not production (Dialogue 002); the pattern that constitutes a system, not its continuity (Dialogue 003). Continuity, identity and outcomes are what one observes; the Canon defines what produces them.

A definition is closed only when both interlocutors declare: *it cannot be improved without losing explanatory power.* Until then, it is marked **candidate**. In practice a definition closes when it ceases to be the discipline's principal source of new explanatory power — when the attacks it still attracts are no longer against it but are using it to discover other things. That is the sign a concept has matured.

Every entry carries four blocks: **Definition · Reason · Boundary Cases · Consequences.**

If a new definition forces changes to several existing ones, it is not yet mature. Each new entry must increase the explanatory power of those already present.

Some terms are **primitives**: accepted without derivation, so that the system has a floor. Every primitive must be marked explicitly — *Primitive term. Not derived.* — wherever it is used as such, so that no one attempts to define it circularly later. Current primitives: **structure** (parts organised in relation; *organised* does not imply intention — a crystal, a snowflake, an ant colony are organised).

The Canon descends only as far as the discipline requires. A deeper primitive that changes no definition above it is noted, not adopted. Knowing where to stop is itself a discipline. *(Pattern rests on distinction/difference — Spencer-Brown, Bateson — but that floor lies outside the discipline's boundary; see Dialogue 004. Pattern is the discipline's operational primitive, the deepest it needs, though not the deepest that exists.)*

## The Ladder

The definitions of this Canon form a ladder. Each level adds a property; none alters the level below.

structure → system → living system → organisation → enterprise → company

A structure is parts organised in relation. A system is a structure that preserves something despite change. A living system is a system whose preserved invariant is the pattern of relations that constitutes it. An organisation is a living system whose constitutive pattern includes a shared purpose across time. An enterprise is an organisation that sustains its purpose through the creation of economic value. A company is a legal form through which an enterprise operates.

The invariant runs through the whole Ladder. Each level does not merely add a property; it specifies the invariant of the level below. A system preserves something; a living system preserves the pattern that makes it itself; an organisation's constitutive pattern includes a shared purpose. One idea — the invariant — gains specificity at each rung.

The discipline's object is the organisation. Its initial market is the enterprise. The Ladder exists so that neither is ever mistaken for the other levels.

## Dualities

The Canon is built not only from definitions but from pairs of concepts that make sense only together. Each pair is the same fundamental duality — *the what and the how; the preserved and the preserver; the object and the mechanism* — seen in a different object.

| What remains | How it remains |
|---|---|
| Pattern | System |
| Identity | Transformation |
| Structure | Architecture |
| Principle | Implementation |

*Principle / Implementation* is not identical to *Pattern / Architecture*; it is that duality projected onto the Ladder of Realisation. This reveals two planes in the Canon: an **ontological** plane (what things are — the first Ladder) and a **realisational** plane (how they come to exist — the Ladder of Realisation). The two Ladders coexist without competing because they answer different questions. Most dualities live on the ontological plane; *Principle / Implementation* lives on the realisational one.

This is why the fifth test holds. *Mechanisms over consequences* is a rule about dualities: the Canon always defines the *how* side (the mechanism), because the *what* side (the observed remaining) is the consequence. The dualities are not decoration; they are the deep structure that generates the fifth test. The great conceptual systems are built this way — pairs, not isolated terms.

## The Ladder of Realisation

Distinct from the ontological Ladder (structure → … → organisation), a second structure runs *downward* — the same pattern descending from principle to matter:

principle → implementation → manifestation
**Pattern → Architecture → Form**

- **Pattern** — the principle: what must be preserved.
- **Architecture** — the implementation: how it is decided to be preserved.
- **Form** — the manifestation: the concrete, replaceable embodiment.

The same pattern (knowledge must outlive people) admits one architecture (distributed organisational memory) and many forms across time (this software today, another in twenty years). This locates a long-avoided answer: **an implementation is not an architecture.** A specific product is a form, or at most a form of an architecture — not the architecture itself. The discipline is thereby freed from any particular product structurally, not rhetorically.

Pattern and Architecture are a duality (*what / how*), not two rungs of one ladder: Architecture is not defined *as* implemented Pattern, or the pair collapses. Architecture retains its functional definition — the structure through which a system observes, remembers, decides and learns — because those verbs are the load-bearing links to the discipline's Papers on observation, memory, judgement and evolution.

## Organisation

**Status: closed (Dialogue 001). Both interlocutors declared: it cannot be improved without losing explanatory power.**

### Definition

An organisation is a living system that coordinates people, knowledge and resources towards a shared purpose across time. Its identity is preserved by its constitutive pattern; its architecture creates the conditions under which that pattern can be preserved; its continuity depends on the system's capacity to decide and to learn — which is why an organisation endures not by what it owns, but by what it can continue to understand.

### Reason

Earlier candidates failed in two directions. A decision-centred definition made decisions the end rather than the means: a university, a hospital, a church does not exist to produce decisions. A coordination-centred definition was true but not distinctive — it did no work the standard management literature does not already do. The present formulation keeps purpose and continuity at the centre and recovers decision and learning as the metabolism that sustains them.

The identity clause was originally a membership criterion — *identity survives the replacement of its members* — which failed the Ship of Theseus test in very small organisations. It was replaced by a mechanism: identity is carried by the architecture, not the members. Dialogue 004 then found this still one level too shallow: what preserves identity is the **constitutive pattern**; the architecture only creates the conditions under which that pattern can be preserved; the system is what preserves it in fact. The final wording separates these so that each concept does one job — Pattern: identity; Architecture: conditions; System: preservation; Living system: self-preservation; Organisation: purpose.

*Living* is not decoration. A living system preserves its constitutive pattern; an organisation that stops deciding and learning does not stand still — it degrades. The second sentence of the definition depends on this premise.

### Boundary Cases

- **A market** — coordinates people, knowledge and resources across time, but has no shared purpose; only aggregated individual purposes. Excluded.
- **A crowd or spontaneous movement** — momentarily shared purpose, no continuity dependent on deciding and learning. Excluded.
- **A project** — coordination with purpose, but it exists in order to end; an organisation exists in order to continue. Excluded by *across time*.
- **A family** — coordination, continuity, something like shared purpose; but its identity does not survive changes in membership, because the members are the identity. Excluded: its constitutive pattern is not independent of its particular members.
- **A two-partner firm losing both founders** — remains the same organisation to the degree that its architecture, not its founders, carries its identity. Where it does not, the system was incomplete. (This is the foundation of the Founder Problem.)

### Consequences

- **The Founder Problem** — an organisation whose identity does not survive the founder is a system that has not yet been built.
- **Organisational Memory** — a system that must learn requires structures that remember.
- **Evolution** — continuity through changing reality requires deliberate change to the architecture.
- **Architecture** — since identity is preserved by architecture, architecture is prior to management.
- **Organisational pathology** — if organisations are living systems, they can sicken, degenerate and die. This becomes a legitimate territory of future investigation.

### Obligations created

- *Living system* must be defined in the Glossary before the Canon uses it further.
- *Architecture* must be defined over **systems**, not over organisations, to avoid circularity.

## System

**Status: closed (Dialogue 002). Both interlocutors declared: it cannot be improved without losing explanatory power.**

### Definition

A system is a structure that preserves a pattern despite change, independently of the particular agents involved.

### Reason

Two attacks moved the definition. The first: a system does not produce outcomes so much as preserve something — a circulatory system, a bridge, a legal system maintain conditions and capacities rather than yield results. Production became a special case of preservation (a factory preserves a capacity to transform). The second was epistemological: the precise term for what is preserved — *invariant* — is opaque to the readers the discipline must reach. It was moved to the Glossary as a technical name and to the Method as an operator of inquiry. The definition first kept a legible gloss — *a condition, a capacity or a pattern of outcomes* — but Dialogue 004 showed this enumeration was three names for one thing: all three are patterns. The enumeration collapsed into the single word **pattern**, now defined one level below. The final clause was freed of anthropocentrism: *particular agents* (person, machine, organism, or none) replaced *who operates it*.

The discriminating work is done entirely by *independently of the particular agents involved*. It is what separates a system from its four neighbours.

### Boundary Cases

- **A habit** — produces consistency, but not independently of the person; it resides in an agent and dies with them. Excluded.
- **A procedure** — a description of steps; produces nothing by itself, and its outcome depends on the operator's fidelity. Excluded.
- **A process** — what actually happens; becomes a system only when structure, not goodwill, guarantees the outcome. Excluded until then.
- **A tool** — amplifies an operator; its outcome depends entirely on who wields it. The inverse of a system, which is why buying tools does not produce systems.
- **A die, a clock, an ecosystem, a bridge** — all systems. Width accepted: scope is narrowed later by *living system* and *organisation*, not here.
- **A rock** — excluded by the primitive: a rock is not *parts organised in relation* in any functional sense.

### Consequences

- **Habit ≠ System** and **Tool ≠ Architecture** receive their foundations.
- **System ≠ Control** — a system requires no controller (ecosystem, market). Decisive for the Observer: observing a system does not require controlling it.
- **The Founder Problem**, restated: a founder-dependent company produces outcomes that are not independent of *who* — it fails the definition of system at its own scale.
- **The operational test:** *if the pattern changes when the agents change, there is no system yet.*

## Pattern

**Status: closed (Dialogue 004). Closed when it ceased to be the discipline's principal source of new explanatory power.**

### Definition

A pattern is what stays the same when the particulars change.

### Reason

The System definition first enumerated three things it preserved — a condition, a capacity, a pattern of outcomes. These are one thing: all are patterns. The single concept beneath them had to be derived. Candidates that spoke of *quality* (Alexander) forced a further undefined term; candidates that spoke of *persistence* or *recurrence* smuggled back the consequence (persistence is what the system explains) or the observer (recurrence requires someone to identify two occurrences as the same). What distinguishes a pattern from any configuration, without any of these, is sameness under change of its particulars — the melody that survives transposition, the ship of Theseus. *Particulars* (not *components*, an underived term; not *parts*, too narrow) means the concrete details of any kind: parts, relations, order, intensity, who embodies them.

Pattern is the discipline's operational primitive — the deepest concept it needs. It rests, logically, on distinction/difference (Spencer-Brown, Bateson), but that floor lies outside the discipline's boundary and is noted, not adopted. Pattern is central not by choice but by derivation: every major concept of the discipline reformulates through it without loss.

### Boundary Cases

- **A heap of sand** — a configuration, but swap one grain and it is another configuration; nothing stays the same. Not a pattern.
- **A melody** — stays the same in another key, on another instrument, sung by another voice. A pattern.
- **The Ship of Theseus** — the question *is it the same ship?* is the question *has the pattern been preserved?* Pattern is the resolution, not the paradox.

### Consequences

- **The enumeration in System collapses** — *condition, capacity, pattern of outcomes* become one word.
- **The two Ladders** — Pattern is the top of the Ladder of Realisation (Pattern → Architecture → Form) and the invariant preserved along the ontological Ladder.
- **Invariant** becomes the technical name for a pattern seen from the point of view of its preservation.
- **The permanent question** — *does a pattern define identity, or the permissible transformations of identity?* — is inherited by a future Paper, not resolved here.

## Living System

**Status: closed (Dialogue 003, simplified once Pattern closed). Both interlocutors declared it cannot be improved without losing explanatory power.**

### Definition

A living system is a system that preserves its constitutive pattern.

### Reason

The first candidate — *a system whose preserved condition is its own continuity* — inverted cause and effect: continuity is not what a living system preserves but what results. An organism continues *because* it maintains the pattern that constitutes it; lose that pattern and continuity vanishes at once. This is autopoiesis (Maturana and Varela). An earlier wording spoke of preserving *its own organisation*, which collided with **Organisation**, the fourth rung of the Ladder; once Pattern closed, the collision dissolved — a living system preserves its *constitutive pattern*, the pattern that makes it itself.

### Boundary Cases

- **A bridge** — a system (preserves a pattern), but not its own constitutive pattern; it does not maintain itself. Not living.
- **A seed / dormant spore** — constitutive pattern preserved, maintaining activity below the observable threshold. Living. Reinforces the definition.
- **A virus** — preserves its constitutive pattern, but cannot reproduce it without another living system's machinery. A parasitic living system — which is why it has been a borderline case for decades. Autonomy is not part of the base definition; the width is accepted, as with the die and the ecosystem.
- **A corpse, a defunct brand, an abandoned building** — the pattern can no longer be preserved; what remains has fallen down the Ladder to structure.

### Consequences

- **Organisational pathology** — living systems can sicken (pattern degraded), degenerate (pattern progressively lost) and die (pattern no longer preservable). A legitimate territory, sanctioned by the Canon rather than by metaphor.
- **Antifragility becomes definable** — a living system improved by the erosion it resists, not merely surviving it. The Canonical footing for Robust ≠ Antifragile.
- **The corpse test** — of anything called living, ask: what is the constitutive pattern it maintains? If none can be named, it is a structure, not a living system.
